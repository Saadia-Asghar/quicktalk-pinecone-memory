# Flask + Pinecone memory service

This service stores customer conversation memories with four required identity fields:

- `organization_id` — mapped to a dedicated Pinecone namespace
- `session_id` — identifies the organizational chat session
- `mobile_no` — normalized customer identity and used in metadata filters
- `timestamp` — UTC ISO-8601 time (generated by the service when omitted)

## Run

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
Copy-Item .env.example .env
.venv\Scripts\python flask_app.py
```

Open `http://localhost:8765` for the Human Agent Inbox. Without a
`PINECONE_API_KEY`, the service intentionally uses `data/pinecone_fallback.json`
for local development.

For Pinecone, create `quicktalk-memories` (or set `PINECONE_INDEX`) as a dense
cosine index with dimension `384`. This demo uses deterministic feature hashing
so it does not require a second embedding API; production should replace
`_embedding()` with the organization's approved embedding model and recreate the
index using that model's dimension.

## API

Store a memory:

```http
POST /api/memories
Content-Type: application/json

{
  "organization_id": "nayatel-demo",
  "session_id": "session-2026-001",
  "mobile_no": "+923331234567",
  "role": "customer",
  "text": "My internet disconnects every evening"
}
```

Search memory:

```http
GET /api/memories?organization_id=nayatel-demo&mobile_no=%2B923331234567&q=internet
```

Load the three-bullet inbox card:

```http
GET /api/inbox/context-card?organization_id=nayatel-demo&mobile_no=%2B923331234567
```

Organization namespaces plus mandatory mobile metadata filters prevent one
organization or customer from retrieving another one's memories.
